# Commodore 64

The Commodore 64 (Commodore, 1982) has a hires bitmap mode of 320×200
pixels in cells of 8×8, 40 across and 25 down. Each cell has two of the
machine's 16 colors, any two: a *foreground*, the color of the bitmap's 1
bits, and a *background*, the color of its 0 bits. A cell's two colors are
stored in one byte, so where colors meet, the cell grid shows, as on the
Spectrum. The C64's multicolor mode, with up to 4 colors per cell and
double-wide pixels, isn't supported yet.

How dithering to cells works in general, and which mode suits which
picture: [README.md](README.md).

## Quick start

```bash
# ordered dithering inside the cells: the classic look
npm run dither-cli -- picture.png screen.png --machine c64-hires --bayer 8

# error diffusion inside the cells, for photos with fine detail
npm run dither-cli -- picture.png screen.png --machine c64-hires --kernel atkinson

# the C64's own files: a program that shows the picture, and an Art Studio picture
npm run dither-cli -- picture.png screen.prg --machine c64-hires --bayer 8
npm run dither-cli -- picture.png screen.art --machine c64-hires --bayer 8
```

The `.prg` and `.art` files need a picture of exactly 320×200 (see
[Size](README.md#size)). In the library, the module is
`Puregrain.Machine.C64`, imported as `C64`: `C64.hiresScreen` is the screen
mode for `Puregrain.Cells`, and `C64.toHiresPrg` and `C64.toArtStudio`
write the files.

```purescript
case bayer 8 of
  Just m -> C64.toHiresPrg (ditherCells noDiffusion (orderedInCell m) C64.hiresScreen picture)
  Nothing -> Left "no 8 × 8 Bayer map"   -- not reached: 8 is a power of 2
```

## The hires cells

Every pair of two colors and every single color: 120 pairs and 16 single
colors, **136 hires cells**, the candidates for each cell
(`C64.hiresCells`).

- **Foreground and background:** the foreground is the darker color, the
  background the lighter, as with the Spectrum's black ink on white paper.
  Darker means a lower luma, 0.299 R + 0.587 G + 0.114 B, since the C64's
  color codes aren't in order of brightness. A single-color cell has
  foreground = background.
- **Order:** the 16 single colors first, by code, then the pairs by the
  distance between their two colors, nearest first; at equal distances,
  by foreground, then by background. On a tie the earlier wins, so a cell
  that several candidates fit equally well gets the narrowest, the
  calmest.
- **Why the order matters:** a picture made only of valid cells must come
  back unchanged. Grey lies on the line from black to white, so a cell of
  black and grey fits black and white perfectly too; only the nearer
  pair, listed first, keeps it as it was.
- **With ordered dithering,** the foreground is the pattern's base: a cell
  is foreground, with background dots added as a pixel nears the
  background.

## The program: .prg

A `.prg` file is a C64 program: the address it loads at, two bytes, low
byte first, then the bytes to load there. Ours shows the picture by
itself. It's 14,145 bytes and loads at 2049, where BASIC programs start:

| Address | Content |
|---|---|
| 2049 ($0801) | the viewer, a BASIC program, then two zero bytes, its end |
| up to 3071 | zeros |
| 3072–4071 ($0C00) | the colors, one byte per cell, row by row: foreground × 16 + background |
| up to 8191 | zeros |
| 8192–16191 ($2000) | the bitmap |

- **The bitmap:** one bit per pixel, 1 for the foreground and 0 for the
  background, the leftmost pixel in the highest bit. Each cell's 8 bytes
  come in a row, its top pixel row first, and the cells row by row. The
  byte of the pixel at (x, y), with integer division:

  ```
  8192 + 320 × (y / 8) + 8 × (x / 8) + y mod 8
  ```

  and its bit is 7 − x mod 8. A single-color cell has all its bits 0.
- **The viewer:**

  ```
  10 B=PEEK(53280):D=PEEK(53265):M=PEEK(53272)
  20 POKE 53265,D AND 239:POKE 53280,0:POKE 53272,56:POKE 53265,D OR 32
  30 POKE 198,0
  40 GET K$:IF K$="" THEN 40
  50 POKE 53265,D AND 239:POKE 53272,M:POKE 53280,B:POKE 53265,D
  ```

  Line 10 notes the border color (53280) and the video chip's two
  registers (53265, 53272), to put them back at the end. Line 20 blanks
  the screen (bit 4 of 53265 off), so nothing half-set shows; makes the
  border black; points the video chip at the colors and the bitmap, 3 ×
  16 + 8 = 56 in 53272 for 3 × 1024 and 8192; and turns bitmap mode on
  (bit 5) with the screen shown again. The video chip reads both where the
  file put them, so nothing is copied, and the picture appears at once.
  Line 30 empties the keyboard buffer (198 counts the keys in it), so a
  key pressed while loading doesn't end the picture straight away; line
  40 waits for a key. Line 50 blanks the screen again, puts everything
  back, and shows the text screen, which the viewer never touched.
- **The BASIC lines** are stored as the C64 stores them: the address of
  the next line and the line number, both low byte first; the text, with
  each keyword one byte (`IF` $8B, `POKE` $97, `GET` $A1, `THEN` $A7,
  `AND` $AF, `OR` $B0, `=` $B2, `PEEK` $C2); and a zero. Unlike the
  Spectrum's, numbers in the text are plain digits.
- **Running it:** open it in an emulator, which starts it.
  - In the browser, [ty64](https://ty64.krissz.hu/): drop the file onto
    it. It shows Colodore's colors by default, as our PNG does, through a
    CRT-TV filter you can switch off. [VICE's online
    version](https://vice.janicek.co/c64) runs it too, in VICE's default
    palette, Pepto's older and duller one.
  - On the desktop, VICE: drop the file onto its window. Choose the
    Colodore palette in its video settings to see the colors as in the
    PNG.
  - On a C64, type `LOAD "name",8` and `RUN`.
- **Colors:** the file holds color codes, not colors, so each emulator
  shows them in its own palette.

## The picture file: .art

Art Studio was the C64's best-known hires paint program, and its files are
the hires format that most viewers and converters open. An `.art` file is
9009 bytes:

| Bytes | Content |
|---|---|
| 0–1 | the address it loads at, 8192 ($2000) |
| 2–8001 | the bitmap, as in the `.prg` |
| 8002–9001 | the colors, as in the `.prg` |
| 9002–9008 | 7 zero bytes of filler |

- **Viewing it:** RECOIL's viewers open it: [in the
  browser](https://recoil.sourceforge.net/web.html), as apps, and as
  plugins for image viewers. RECOIL has a C64 palette of its own, Pepto's
  older one, so the picture looks duller than the PNG.
